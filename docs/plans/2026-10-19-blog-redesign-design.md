# blackball blog redesign — design

> Status: approved 2026-10-19
> Direction: **a terminal that reads like a book**

## Context

`blackball` is a small personal blog with seven Chinese essays. The current
site is generated by a 64-line `update.py`, keeps all posts in one index, and
uses a narrow black-and-green layout. The content is literary; the site should
feel like a quiet reading room while retaining the personality of the original
terminal aesthetic.

## Goals

1. **More convenient to write for.** Adding a Markdown file and pushing to
   GitHub should be enough to publish. The build must work on Windows and
   Linux, fail with useful messages, and preserve every existing URL.
2. **A better reading experience.** Long essays need comfortable typography,
   a table of contents when useful, previous/next navigation, progress, and a
   light/dark reading mode.
3. **A distinctive, coherent visual identity.** Refined terminal, not neon
   nostalgia: deep ink-green surfaces, phosphor accents, editorial hierarchy,
   mono details, and generous negative space.
4. **A maintainable codebase.** One build entry point, templates separated from
   content, and generated pages clearly marked and safely cleaned up.

## Non-goals

- Tags, full-text search, comments, analytics, or pagination (not enough
  posts yet; these can be added without changing the content model).
- Migrating to a general-purpose SSG or a JavaScript framework.
- Rewriting or restyling the essays themselves.

## Approach

Keep the custom Python generator and evolve it. This preserves the Markdown
files, GitHub Pages hosting, and the "edit anywhere" workflow. A migration to
Hugo or Astro would add a toolchain and make editing through GitHub less
convenient.

### Content model

- Posts live in `posts/` as `YYYY-MM-DD-slug.md`.
- The first line beginning with `## ` is the title; it is removed from the body
  so the title is not duplicated.
- The filename supplies the date and the URL. Existing URLs, including
  `02023-08-06-about.html`, are preserved.
- The first paragraph supplies the summary. Reading time is estimated from
  Chinese characters and Latin words.
- `site.json` owns the site title, tagline, description, navigation, author,
  URL, and footer copy.

### Build pipeline

1. Load and validate `site.json`.
2. Read posts, validate filenames and dates, extract titles, compute summaries
   and reading times.
3. Render Markdown with tables, fenced code, footnotes, sane lists, syntax
   highlighting, and heading IDs/TOC data.
4. Render pages from `templates/base.html`, `index.html`, `post.html`, and
   `404.html` using a tiny `{{ key }}` renderer. No template engine dependency.
5. Write `index.html`, one `html/<stem>.html` per post, and `404.html`.
6. Delete only stale files that carry the generated-file marker.
7. Offer `--serve` for a local preview.

The only runtime dependencies are `Markdown` and `Pygments`, pinned in
`requirements.txt`.

### Pages

- **Home:** masthead, statement, author/status card, featured latest post,
  remaining posts grouped by year.
- **Post:** metadata, reading time, summary, optional sticky TOC (2+ headings),
  previous/next navigation, end mark, reading progress.
- **404:** themed fallback with a path back home.

## Visual system

### Palette

Dark mode is the canonical experience: near-black green-tinted ground, soft
phosphor green accent, warm grey-green body text, and a lotus-pink punctuation
accent drawn from the logo. Light mode is a warm paper interpretation, not a
simple inversion.

### Typography

- **Chinese body and titles:** `Noto Serif SC` (weights 400/500/600/700),
  falling back to Source Han Serif SC, Songti SC, STSong, and SimSun.
- **UI, metadata, Latin, and code:** `IBM Plex Mono` (400/500), falling back to
  Cascadia Code, Sarasa Mono SC, and generic monospace.
- Body size 17–19px with a line height near 2.0, a 44rem reading measure, and
  generous paragraph spacing. Latin/mono text is smaller and tracked out.
- Webfonts load from Google Fonts with `display=swap`; the site remains fully
  readable with local fallbacks if that request fails.

### Composition and detail

- Sticky, blurred masthead with a small lotus seal.
- Asymmetric hero: oversized serif statement on the left, compact terminal
  status panel on the right.
- Hairline rules, faint grid/vignette, outlined numerals, and restrained
  hover motion.
- One purposeful entrance sequence and scroll reveals; reduced-motion users
  get the final state immediately.
- Responsive from 320px upward; no horizontal scrolling.

### Interaction

- Pre-paint theme initialization (stored preference, otherwise system).
- Accessible theme toggle with `aria-label` updates.
- Reading-progress line and active TOC highlighting on post pages.
- Copy buttons for code blocks.
- Back-to-top control after scrolling.
- Visible focus states, skip link, semantic landmarks, and alt text.

## Publishing

Add `.github/workflows/publish.yml` that builds with Python 3.12 and deploys
the generated site through GitHub's official Pages actions. No bot commits and
no rebuild loops. One-time repository setup is required: **Settings → Pages →
Build and deployment → Source: GitHub Actions**. Generated HTML stays committed
so the site also works when served from the branch, and local previews remain
accurate.

## Error handling

- Missing `site.json`, invalid JSON, missing required fields: stop with the
  file and field named.
- Bad post filename/date, missing `##` title, duplicate output names: stop and
  identify the post.
- Missing Python packages: print the exact `pip install -r requirements.txt`
  command.
- Cleanup is marker-based: only previously generated HTML is removed.
- The build reports generated page count and elapsed time.

## Verification

- Build all existing posts with no warnings.
- Validate every generated page's HTML structure and internal links with a
  Python checker.
- Check unique titles, present metadata, and preserved URLs.
- Use a real headless browser (Edge) at desktop and mobile widths in both
  themes; check layout, console errors, theme persistence, TOC, copy buttons,
  and previous/next links.
- Confirm no horizontal overflow at 320, 768, 1440, and 1920 widths.
